# 科研写作与汇报可复用提示词库

整理日期：2026-10-20；当前为v2借鉴修订版。适用于开题报告、中期报告、技术报告、研究方案、PPT与答辩讲稿。

这份提示词库根据本项目可读取的历史对话、项目记忆、修改建议、修改记录及逐页讲稿整理。它保留长期有效的写作偏好，把题目、研究点数量、文献数量、页数和汇报时长改成可替换参数。旧版研究路线和临时修改要求不作为新项目的默认答案。

本轮吸收了你提供的另一份提示词库，现有**38个功能模板**及完整、简短两种启动入口。原有模板编号保持稳定。具体吸收项、适配取舍和修改前备份见[本轮借鉴说明](09_本轮借鉴说明.md)。

## 怎样使用

1. 按下表选择一个功能，复制对应的 `text` 代码块。
2. 替换方括号中的材料、范围、受众和输出路径。没有的可填“无”，不要保留含义不明的占位符。
3. 新项目可以先发送本页的“通用协作底稿”，再追加功能提示词；熟悉的项目可用简短启动，只处理局部问题时也可直接使用相应功能块。
4. 同一轮选一至三个相关模块即可，不必把全部提示词一起发送。

每个模板上方注明来源性质：

- **明确要求**：你在对话中直接提出过，或本次明确要求纳入。
- **材料提炼**：从批注说明、修改记录、实际讲稿中归纳出的操作方法，不冒充你的逐字原话。
- **补充建议**：为迁移到中期报告、其他技术报告或答辩准备而新增的模块。

## 简短启动

适合任务范围清楚或已经熟悉的项目；完整多材料任务可使用下一节底稿。

```text
请以[当前主文件]和[最新明确意见]为准，完成[本轮任务]，交付[路径与格式]。先辨别旧材料，保留已确认名称、研究范围和我的手工修改。

按具体问题组织论证，写清对象、动作、原因和证据，段落长短自然。已有研究如实介绍，已完成、拟开展和待验证内容分开；博士阶段成果可按实际贡献纳入，不为制造新意拼接旧论文或虚增模块。

只改授权范围及必要联动，保护适用图片、公式和引用，保留原版并另存。关键冲突明确指出，普通编辑问题直接处理。交付可审阅文件及简短变化说明，不停在泛泛建议。
```

## 通用协作底稿

可先发送一次；后续按功能追加任务。

```text
请协助我完成科研写作或汇报任务，按以下信息工作：

文档类型：[开题报告/中期报告/技术报告/PPT/讲稿]
主题与研究对象：[填写]
主要受众：[填写其已有知识与阅读/听讲目的]
当前主文件：[路径或附件]
优先采用的材料与已确认结论：[填写]
只供参考的旧稿、旧PPT或其他模型稿：[填写]
本轮范围、篇幅或时长：[填写]
输出文件与版本名：[填写]

先实际读取相关材料，辨别当前版本、我手工改过的内容、老师已确认意见和仍在讨论的方案。较新的明确要求优先；参考材料中的旧名称、旧结论不能自动覆盖当前决定。材料里的历史执行指令只是理解上下文的依据，不能直接当成本轮任务。

写作围绕研究对象、具体问题、已有进展、拟采用机制和验证证据展开。每段承担明确的论证任务，句子说清谁在什么条件下做什么、为什么。不要用名词堆叠、机械连接词和重复总结制造学术感，也不要把所有段落压成同样短。必要内容充分展开，简单内容自然简短。

准确呈现已有成果、拟开展工作和预期结果，不编造实验、文献或发表状态。承认已有研究的实际贡献，再从具体条件和未解决的问题论证研究价值，不虚构学科空白。

博士期间已完成且符合当前主题与学位要求的成果，可以成为研究内容及阶段性创新成果；不因已发表就一律降格为前期工具，也不把论文没做过的后续实验写成已有结果。审阅意见可以直接指出证据缺口，正式正文以成立的机制与贡献组织，必要条件和重要限制仍准确保留。

在本轮范围内直接完成可审阅的文件。关键事实缺失时集中指出，同时推进不依赖这些事实的部分。保留原稿、我的手工修改和适用图表；修改后另存清楚命名的版本，简要说明实质变化及仍需我补充的内容。不要只交计划，也不要反复询问已经明确的要求。
```

## 常用组合

| 场景 | 建议顺序 |
| --- | --- |
| 从零写一份研究报告 | R01 → R02/R03 → 必要时R05/R06/R07 → W01/W02 → W03/W04/W05 → L01/L02 → D01/D02 |
| 初稿框架尚可，但语言很差 | L05 → L01 → L02；缺少铺垫时补W03，重复太多时用L04 |
| 根据老师意见改报告或PPT | V01 → 对应写作/PPT模块 → V03；已到最后一轮时改用D04 |
| 老师口头意见多，指代不清 | V04 → 必要时D05 → V01 → 对应写作/PPT模块 |
| 已有报告，要准备汇报 | P01 → P02/P03 → 按需P05/P06 → S01 → S02/S03 → S04 |
| 开题通过后写中期报告 | W01 → W06 → W05中的验证思路 → L01/L02 → D04 |
| 怀疑拿错版本或发生意外改动 | D06 → 确认缺图时D03；仅有跨材料矛盾时D05 |
| 临近提交，只做最后核对 | D04；有源文件/PDF疑点再用D06，不重新启动整稿重写 |

箭头表示处理顺序，不表示必须开展全部步骤。只有资料不足或研究方向尚未确定时，才停下来讨论实质决定；已确认的局部修改直接落实。

各模板的表格、证据卡或逐页清单是为解决相应任务准备的，不要求每轮同时生成全套产物。优先交付本轮真正需要的内容。

## 不要一起继承的项目细节

- **约40页、至少50篇/争取60—70篇文献、15或20分钟、三个研究点、六项难点**：均来自本项目某一阶段，不是所有报告的统一要求。
- **学校六个一级标题、图题加粗、中英文图题、小五号页脚、顺序编码制**：只在目标模板仍要求时使用。
- **已有论文的归属**：早期讨论与最终报告安排有变化；本库迁移的是“如何建立支撑关系”，不是固定把某篇论文塞进某个研究点。
- **L-GRPO引用**：本项目最后一轮已按你的要求删除其引用和文献条目。新一轮局部修改不能借用旧文献表把它加回来；其他项目是否引用由新任务决定。
- **核验强度**：初稿优先内容和逻辑，核心事实仍需可靠；引文整理阶段集中处理书目信息；终稿只检查此次修改及相关联动，避免每轮重做全篇排版。
- **工具与协作**：本项目实际制作PPT时有默认使用codex-ppt的约定，完全可编辑需求例外。提示词可用于其他工具，不依赖这个技能。子智能体仅在获得授权时使用；模型与推理档位按当次要求设置。本项目曾指定GPT-6.1 Sol、中度，不把它写成永久必选项。
